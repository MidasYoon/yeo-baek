# 여백 (yeo-back)

여행 한 건을 기록하고, 방문한 곳은 **지도와 목록**으로, 그날의 이야기는 **날짜별 일기**로 모아 보는 여행 다이어리 웹앱입니다.
3~4일 바이브 코딩 팀 프로젝트 MVP입니다.

## 현재 상태

- 구현 단계입니다. 화면 틀(`frontend/`: 네비와 빈 화면 4개, 없는 주소 화면)을 만들었습니다. 서버 틀(`backend/`)과 테이블 3개(`trips`, `places`, `diaries`)를 만들었습니다. 목록 API 3개와 화면·서버 연결(Vite 프록시)을 만들었습니다. 공통 부품 4개(버튼, 상태 표시, 지우기 확인 창, 여행 select)를 만들었습니다(뒤에 사진 칸과 페이지 버튼을 더함). 여행기록 API(목록·하나·만들기·고치기·지우기)와 여행 목록·추가·상세·수정·삭제 화면(`/trip`, `/trip/new`, `/trip/:id`, `/trip/:id/edit`)을 만들었습니다. 장소 API(목록·최근 1개·하나·만들기·고치기·지우기)와 장소 목록·추가·수정·삭제 화면(`/place`, `/place?trip=`, `/place/new?trip=`, `/place/:id/edit`)과 지도·핀을 만들었습니다. 일기 API(목록·최근 1개·하나·만들기·고치기·지우기)를 만들었고, 다이어리 목록 화면(`/diary`, `/diary?trip=`)을 만들었습니다. 일기 쓰기·고치기·삭제 화면(`/diary/new?trip=`, `/diary/:id/edit`)도 만들었습니다. Home 화면(`/`, 큰 문구·한옥 그림·최근 여행/장소/일기 카드)을 만들었습니다. 여행 상세(`/trip/:id`) 아래에 그 여행의 장소·일기 목록을 붙였습니다.
- 여행 대표사진(0~1장)·장소 사진(0~4장)·일기 사진(0~1장)을 더하기로 팀이 합의했습니다 (D-033). 사진 올리기·보기 API(`/api/uploads`)와 공통 사진 칸 부품을 만들고, 여행(작성·수정·상세·목록), 장소(폼·카드), 일기(폼·펼친 줄)에 사진을 넣었습니다.
- TEST-PLAN 검사 230개를 모두 통과했습니다 (2026-10-23, PLAN P-21). 이 상태에 기준 태그 `v0.1-mvp`를 달았습니다 (커밋 `0a3bcfd`). 그 뒤에 더한 기능(아래 전체 보기, AI 여행지 추천 등)은 이 태그에 들어 있지 않습니다.
- 장소·일기 화면에 들어가면 "전체 여행"으로 모든 여행의 장소·일기가 최신순으로 보이고, 장소는 10곳·일기는 20편씩 페이지로 나뉩니다 (D-034, PLAN P-40~P-44). 이를 위해 전체 목록 API(`/api/places/page`, `/api/diaries/page`)와 공통 부품 페이지 버튼을 더했습니다. Home 최근 장소·일기 카드는 그 여행을 고른 채로 가고, 최근 일기는 펼친 채로 보입니다 (2026-10-23 팀 합의).
- 여행지 정보의 지도를 카카오맵으로 바꿨습니다 (D-036, PLAN P-45~P-50). 장소는 카카오 장소 검색으로 골라야 저장되고, 시·도와 좌표가 자동으로 채워집니다. 같은 곳을 여러 번 다녀왔으면 핀 하나에 개수가 보입니다. 카카오맵을 불러오지 못하면 전의 그림 지도가 대신 보입니다. `places` 테이블에 좌표 칸 3개가 더해졌고, 이미 있는 DB에는 백엔드를 켤 때 자동으로 더해집니다(넣어 둔 데이터는 그대로).
- 화면을 길게 내리면 오른쪽 아래에 "맨 위로" 버튼이 나타납니다 (2026-10-23, PLAN P-65).
- 장소에 별점(1~5)을 청사초롱으로 매깁니다 (D-042, PLAN P-70~P-72). 장소를 넣거나 고칠 때 꼭 골라야 하고, 장소 카드(여행 상세 포함)에 불 밝힌 초롱 수로 보입니다. 별점이 생기기 전에 넣은 장소는 비어 있어 초롱 줄이 없고, 고칠 때 별점을 골라야 저장됩니다. `places` 테이블에 `rating` 칸이 더해졌고, 이미 있는 DB에는 백엔드를 켤 때 자동으로 더해집니다. Home 최근 장소 카드에는 보이지 않습니다 (P-73 뺌).
- 기분을 이모지 대신 귀여운 하회탈로 그리고, 장소 지도 핀을 솟대로 바꿨습니다. 로딩 표시는 잠깐 뒤에 색동 마름모와 함께 나타나 빠른 로딩에서 깜빡이지 않습니다 (2026-10-23, PLAN P-63~P-64).
- 화면 등장, 목록 차례 등장, 메뉴 밑줄, Home 도장·인장, 한옥 그림 속 구름·청사초롱, 여행 표지 기울임, 일기 펼침 같은 움직임과 바탕의 한지 결을 더했습니다. 움직임 줄이기를 켜면 멈춥니다 (2026-10-23, PLAN P-62).
- 세 목록 화면을 섹션 컨셉으로 꾸몄습니다: 여행 기록은 "여행 책장"(책 표지 카드, 기사 모양 상세), 여행 장소는 "답사 수첩"(지도 액자, 지역 도장), 여행 일기는 "여행 일기장"(공책 여백선, 줄노트, 폴라로이드 사진). Home 한옥 그림을 다시 그렸습니다 (2026-10-23, PLAN P-57~P-61).
- 화면 폭을 1080px로 줄이고, 여행·장소·일기의 추가·수정 화면은 제목과 폼을 720px 칸 가운데에 두었습니다. 일기 날짜 묶음에 요일을 더하고 펼친 본문 한 줄을 680px로 줄였습니다. Home은 표지 줄·창호 액자·인장으로 한옥 매거진 모양을 더했습니다 (2026-10-23 팀 합의, PLAN P-52~P-56, `docs/DESIGN.md`).
- 버튼 크기를 하나로 맞췄습니다 (높이 48px, 글자 15px). 장소 카드의 수정·삭제는 다른 화면과 같은 보조 버튼으로 바꾸고, "장소 추가"는 다른 목록처럼 제목 오른쪽으로 옮겼습니다. 추가 버튼 글자는 "여행 추가·장소 추가·일기 추가", 수정 화면 제목은 "○○ 수정", 사진 칸 버튼은 "사진 추가"·"사진 변경"으로 맞추고, 폼의 사진 빼기는 사진 오른쪽 위 × 버튼으로 바꿨습니다 (`docs/DESIGN.md` 6절).
- 제품 요구 문서(`docs/PRD.md`)를 작성했습니다.
- 구조 문서(`docs/ARCHITECTURE.md`)를 작성했습니다.
- 화면 명세(`docs/SCREEN-SPEC.md`)를 작성했습니다.
- 데이터 모델(`docs/DATA-MODEL.md`)을 작성했습니다.
- API 명세(`docs/API-SPEC.md`)를 작성했습니다.
- 시험 계획(`docs/TEST-PLAN.md`)을 작성했습니다.
- 디자인 문서(`docs/DESIGN.md`)를 작성했습니다. 화면 모양은 "한지 노을" 시안을 따릅니다 (D-023).
- 앱 안에는 AI 기능을 넣지 않기로 했었지만, AI 여행지 추천 하나만 예외로 더하기로 팀이 합의했습니다 (D-037). 오른쪽 아래 버튼을 누르면 대화창에서 기분·여행 스타일·동행·기간을 고르고, AI(Google Gemini 무료 등급, D-038)가 국내 도시 3곳을 추천합니다. 문서(P-66), 추천 API(P-67), 버튼과 대화창(P-68), 화면과 API 연결(P-69)을 만들었습니다. Gemini가 Google 서버 오류를 내면 가벼운 모델(`gemini-3.5-flash-lite`)로 한 번 더 보냅니다 (D-039, D-040). 각자 `backend/.env`에 `GEMINI_API_KEY`를 넣어야 추천을 받을 수 있습니다. 2026-10-23 사람의 지시로 기준점 태그(`v0.1-mvp`)를 달기 전에 만들었고, 태그에는 들어 있지 않습니다.

## 주요 기능

```text
여행기록 (서준)             여행명, 여행지, 기간, 여행 정보
 ├─ 여행지 정보 (은희)      카카오맵(핀) + 목록
 └─ 여행 다이어리 (건용)    날짜별 일기 + 기분
```

- **여행기록**: 여행명, 여행지, 기간, 여행 정보를 기록합니다. 대표사진을 1장까지 붙일 수 있습니다.
- **여행지 정보**: 방문한 여행지를 카카오맵과 목록으로 보여 줍니다. 장소는 카카오 장소 검색으로 고릅니다 (D-036). 장소마다 사진을 4장까지 붙일 수 있습니다. 장소마다 별점 1~5를 청사초롱으로 매깁니다 (D-042).
- **여행 다이어리**: 여행 중 날짜별로 일기를 씁니다. 일기마다 사진을 1장까지 붙일 수 있습니다.
- 장소와 일기는 `trip_id`로 여행에 연결됩니다.
- 첫 화면(Home, `/`)은 세 기능의 데이터를 모아 보여 주는 화면입니다.
- **AI 여행지 추천** (팀 공동, D-037): 모든 화면 오른쪽 아래 버튼 → 대화창에서 취향을 고르면 AI가 국내 도시 3곳을 추천합니다. 추천은 저장하지 않습니다.
- **만들지 않는 것:** 로그인, 실시간 위치 추적, 지도 API·길찾기, 날씨 API, 외부 장소 검색, 여행지 추천, 통계·차트, 검색·필터·별점, 사진 업로드 (위 여행·장소·일기 사진은 예외, D-033. 여행지 정보의 카카오맵과 카카오 장소 검색은 예외, D-036. 길찾기는 여전히 만들지 않음. 위 AI 여행지 추천은 예외, D-037. 장소 별점(1~5, 청사초롱)은 예외, D-042. 별점으로 검색·필터·정렬은 여전히 만들지 않음)


## 실행 방법

> 아래 버전과 명령은 D-024로 확정했습니다. 2026-10-23 Windows PowerShell에서 아래 "매번 켜기" 명령(`Activate.ps1`로 venv 켜기)으로 두 서버를 다시 켜, 전에 넣은 데이터와 사진이 그대로 보이는 것을 확인했습니다 (PLAN P-20).

**준비물:** Python 3.10+, Node.js 20+

**처음 한 번**

```bash
cd backend
python -m venv venv
venv\Scripts\activate          (cmd)
.\venv\Scripts\Activate.ps1    (PowerShell)
pip install -r requirements.txt
```

```bash
cd frontend
npm install
```

카카오맵 키(D-036): `frontend/.env.example`을 같은 폴더에 `frontend/.env`로 복사하고 `VITE_KAKAO_MAP_KEY=` 뒤에 카카오 JavaScript 키를 넣습니다. 키는 팀이 함께 쓰는 카카오 개발자 앱(팀 관리에 팀원 등록)의 "앱 키 > JavaScript 키"에서 봅니다. `.env`는 Git에 올리지 않습니다. 키가 없으면 장소 화면에 그림 지도가 대신 보이고, 장소를 추가하거나 고칠 수 없습니다.

**매번 켜기** — 터미널 2개, 백엔드 먼저

| 위치 | 명령 | 주소 |
| --- | --- | --- |
| `backend/` (venv 켠 상태) | `uvicorn main:app --reload --port 8000` | http://localhost:8000/docs |
| `frontend/` | `npm run dev` | http://localhost:5173 |

- 포트는 백엔드 8000(FastAPI 기본값), 프론트엔드 5173(Vite 기본값)으로 확정했습니다.
- PowerShell에서 `Activate.ps1`이 실행 정책 때문에 막히면, venv를 켜지 않고 `backend/`에서 `.\venv\Scripts\python.exe -m uvicorn main:app --reload --port 8000`으로 켭니다 (D-026).
- DB 파일(`backend/yeoback.db`, D-026)은 Git에 올리지 않습니다. 데이터를 초기화하려면 서버를 끄고 지운 뒤 다시 켜면 됩니다.
- `.env`를 고친 뒤에는 `npm run dev`를 껐다 켜야 키가 들어갑니다.
- 사진 기능(D-033)을 넣으면 테이블 모양이 바뀌므로, 그때 각자 `backend/yeoback.db`를 한 번 지우고 다시 켜야 합니다. 넣어 둔 데이터는 사라집니다.
