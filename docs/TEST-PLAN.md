- 데이터를 바꾸는 검사를 한 뒤에는 백엔드를 끄고 DB 파일을 지운 다음 다시 켜고, 위 데이터를 다시 넣어 되돌린다 (README 실행 방법).
- 장소 별점(D-043)은 `POST`·`PUT`에 꼭 있어야 하므로 예시 장소에 별점을 넣었다 (2026-10-23). 다른 검사에서 장소를 넣거나 고칠 때 별점을 따로 적지 않았으면 3을 넣는다. 별점이 없는 기존 장소는 T-P-100의 DB 복사본으로 본다.
- 사진 검사(D-033)에 쓸 파일을 미리 준비한다 (AI 제안): `small.jpg`(1MB 안팎), `small.png`, `small.webp`, `big.jpg`(5MB 넘음), `wrong.gif`. 사진 검사 뒤에는 DB 파일과 함께 `backend/uploads/` 안의 파일도 지운다.
- **회원 (D-042 뒤, AI 제안):** 빈 DB에서 먼저 회원 1(아이디 `tester1`, 닉네임 "검사 하나")로 가입하고, 로그인한 채로 위 예시 데이터를 넣는다. 그래서 여행 1~4의 주인은 회원 1이다. 이어서 회원 2(아이디 `tester2`, 닉네임 "검사 둘")로 가입한다. 비밀번호는 규칙(8~20자)에 맞는 검사용 값을 각자 정해 쓰고, 실제로 쓰는 비밀번호는 쓰지 않으며 검사 기록에도 적지 않는다.
- `http://localhost:8000/docs`에서 가입·로그인하면 8000 주소에 쿠키가 생겨 이후 요청에 함께 간다. 다른 회원으로 바꿀 때는 `POST /api/users/login`을 다시 부른다. 로그인하지 않은 요청은 `POST /api/users/logout` 뒤에 보낸다.
- 2~6절의 만들기·고치기·지우기 검사는 회원 1로 로그인한 채로 한다. 로그인하지 않은 경우와 남의 기록은 9절에서 본다.

## 8. AI 여행지 추천 (담당: 팀 공동)

> 근거: D-037, PRD 6절, SCREEN-SPEC 7절, API-SPEC 6절, DESIGN 6절. 근거 문서의 문구·모양·응답 모양은 AI 제안을 2026-10-23 사람이 확정했다.

### 1. 검사 전 준비할 데이터

- 1절 예시 데이터를 쓴다. 추천은 DB를 쓰지 않으므로 데이터가 없어도 된다.
- **키 있음:** `backend/.env`에 자기 Gemini 키를 `GEMINI_API_KEY=…`로 넣고 (D-038) 백엔드를 켠다. 키 값은 화면·채팅·검사 기록에 적지 않는다.
- **키 없음:** `backend/.env`의 `GEMINI_API_KEY` 줄을 지우거나(또는 `.env` 파일을 다른 이름으로 바꾸고) 백엔드를 다시 켠다. 검사 뒤 되돌린다.
- **틀린 키:** `GEMINI_API_KEY=wrong-test-key`처럼 지어낸 값을 넣고 백엔드를 다시 켠다. 검사 뒤 되돌린다.
- AI를 실제로 부르는 검사(T-A-07, T-A-12, T-A-14, T-A-19)는 Gemini 무료 한도를 쓴다. 한 번씩만 한다.
- AI 응답은 매번 다르므로 도시 이름·문장은 검사하지 않는다. 개수·모양·시·도 이름만 본다.
