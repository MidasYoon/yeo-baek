## 1. 공통 (팀 합의)

### 한 줄 소개
여행 한 건을 기록하고, 방문한 곳은 지도와 목록으로, 그날의 이야기는 날짜별 일기로 모아 보는 여행 다이어리 웹앱.

### 기능 구성
| 기능 | 담당 | 근거 |
| --- | --- | --- |
| 여행기록 | 서준 | D-001 |
| 여행지 정보 | 은희 | D-002 |
| 여행 다이어리 | 건용 | D-003 |
| Home (`/`) | 은희 | D-004 |
- 장소와 일기는 `trip_id`로 여행에 연결된다.

### 만들지 않는 것
로그인, 실시간 위치 추적, 지도 API·길찾기, 날씨 API, 외부 장소 검색, 여행지 추천,
통계·차트, 검색·필터·별점, 사진 업로드 (README와 같음)

### 열린 질문 (여러 기능에 걸친 것)

## 2. 여행기록 (담당: 서준)

### 1. 목적
어떤 여행을 했는지 한 건씩 기록한다. 그 여행의 장소와 일기를 모아 보는 기준이 된다.

### 2. 사용자가 할 수 있는 일
- 여행을 등록한다. (R-001)
- 여행 목록을 본다. (R-006)
- 여행 하나를 열어 본다. (R-008)
- 여행을 고친다. (R-010)
- 여행을 지운다. 지우기 전에 "정말 지울까요?"라고 한 번 더 묻는다. (R-011)

### 3. 입력하는 정보
| 항목 | 필수 | 규칙 | 예 |
| --- | --- | --- | --- |
| 여행명 | 필수 | | |
| 여행지 | 필수 | | |
| 시작일 | 필수 | `YYYY-MM-DD` | |
| 종료일 | 필수 | `YYYY-MM-DD`. 시작일보다 빠르면 저장되지 않는다. 같은 날은 된다 | |
| 여행 정보 | 선택 | 자유 메모 한 칸 | 친구와 3박 4일 |
- 필수 항목을 비우면 저장되지 않는다. (R-002 ~ R-005)

### 4. 보는 규칙
- 목록은 시작일이 늦은 여행이 위에 보인다. (R-007)
- 여행을 열면 여행 내용과 함께 그 여행의 장소 목록과 일기 목록이 보인다. (R-009)

### 5. 다른 기능과의 연결
- 장소(여행지 정보)와 일기(여행 다이어리)는 여행 한 건에 속한다.
- 여행을 열면 그 여행의 장소와 일기만 보인다. (R-009)

### 6. 이 기능에서 따로 만들지 않는 것
| 넣지 않는 것 | 이유 |
| --- | --- |
| 여행 정보를 여러 칸(동행, 목적 등)으로 나누기 | 서준이 자유 메모 한 칸(R-003)을 고름 (R-013) |
| 목록 정렬 순서 바꾸기 | README "검색·필터"와 맞닿음 (R-015) |
| 지운 여행 되살리기(휴지통) | README "주요 기능"에 없음 (R-015) |

## 3. 여행지 정보 (담당: 은희)

> 근거 결정: D-002 "방문한 여행지를 지도와 목록으로 보여 준다."
> 3~4일 일정과 서준 절(R-009, R-012, R-017)에 맞춰 범위를 줄였다. "팀 확인 필요"가 붙은 내용은 확정이 아니다.

### 1. 목적
여행 하나를 고르면 한국 지도와 핀이 보인다. 핀을 누르면 그 지역에서 다녀온 장소 카드가 보인다.
그 여행의 장소 전체 목록은 여행 상세 화면(서준, R-009)에서 본다.

### 2. 사용자가 할 수 있는 일
| 행동 | 사용자가 겪는 일 |
| --- | --- |
| 여행 고르기 | 화면 위쪽 여행 select에서 여행을 고르면 그 여행의 지도와 핀이 보인다 |
| 장소 추가 | 고른 여행에 장소를 넣는다. 필수 항목을 비우거나 규칙을 어기면 저장되지 않는다 |
| 장소 보기 | 핀을 누르면 지도 아래에 그 지역의 장소 카드가 보인다 |
| 장소 수정 | 카드의 수정 버튼을 누르면 추가와 같은 폼으로 고친다. 규칙도 추가와 같다 |
| 장소 삭제 | 카드의 삭제 버튼을 누르면 지우기 전에 한 번 더 묻고, 확인해야 지워진다. 되돌릴 수 없다 |

### 3. 입력하는 정보
| 항목 | 필수 | 규칙 | 예 |
| --- | --- | --- | --- |
| 지역 | 필수 | 시·도 17개 중 select로 고른다 | 서울 |
| 장소 이름 | 필수 | 20자 이하 | 경복궁 |
| 방문 날짜 | 필수 | `YYYY-MM-DD`, 그 여행의 기간 안의 날짜만 | 2026-05-01 |
| 메모 | 선택 | 20자 이하, 한 줄 | 줄이 길었지만 좋았음 |
- 시·도 17개: 서울, 부산, 대구, 인천, 광주, 대전, 울산, 세종, 경기, 강원, 충북, 충남, 전북, 전남, 경북, 경남, 제주
- 긴 이야기는 여행 다이어리에 쓴다. 장소 메모는 짧게 둔다.

### 4. 보는 규칙
**화면에 들어오는 길**
- 네비 메뉴의 place로 들어온다. 처음에는 여행 select가 비어 있고 "여행을 골라 주세요" 안내가 보인다. (L-07)
- Home의 "최근 장소" 카드를 눌러도 같은 처음 모습으로 들어온다. (H-03)
- 여행 상세에서 고른 여행을 넘겨받아 들어오는 길(L-08)은 이번 MVP에서 만들지 않는다.

**지도**
- 한국 지도 그림(SVG) 1장 위에 핀을 찍는다. 지도 API는 쓰지 않는다. (L-02)
- 핀은 고른 시·도 구역의 가운데에 찍힌다. 사용자가 지도를 클릭해 찍지 않는다.
- 같은 시·도의 장소는 핀 하나로 겹치고, 핀 위에 장소 개수를 표시한다. (L-10)

**핀과 카드**
- 여행을 고르면 지도와 핀만 보인다. 핀이 하나뿐이어도 눌러야 카드가 보인다.
- 핀을 누르면 지도 아래에 그 지역의 장소 카드만 뜬다. (L-12)
- 다른 핀을 누르면 카드가 그 지역 것으로 바뀐다. 같은 핀을 다시 누르면 닫힌다.
- 여행 select를 바꾸면 처음 모습으로 돌아간다.

**카드**
- 장소 이름, 방문 날짜, 메모와 수정·삭제 버튼이 보인다. 따로 상세 다이얼로그는 두지 않는다.
- 방문 날짜가 오래된 순이고, 날짜가 같으면 먼저 추가한 장소가 앞이다. (L-11) 사용자가 순서를 바꿀 수 없다.

**여행별 장소 목록**
- 한 여행의 장소 전체를 카드와 같은 순서로 돌려주는 목록을 둔다.
- 여행 상세 화면(서준)의 장소 목록이 이 목록을 쓴다. (R-009, 은희 제안, 서준 확인 필요)

### 5. 다른 기능과의 연결
- 장소는 반드시 여행 하나에 속한다 (`trip_id`).
- 방문 날짜를 검증하려면 여행의 시작일·종료일이 필요하다. (L-05)
- 여행 select는 여행 목록 API(서준)를 쓴다. (L-09)
- 여행 상세의 장소 목록은 이 기능의 여행별 장소 목록을 쓴다. (R-009, 서준 확인 필요)
- 장소가 있는 여행은 지울 수 없다. 여행에 장소가 있는지는 여행별 장소 목록으로 안다. (R-012 서준 안, 팀 확인 필요)
- 여행 기간을 고쳐 이미 넣은 장소의 방문 날짜가 기간 밖으로 나가는 경우 (R-017, L-04)
  - 제안 (미확정): 이미 넣은 장소는 그대로 둔다. 그 장소를 고칠 때만 기간 안의 날짜여야 저장된다.

### 6. 이 기능에서 따로 만들지 않는 것
| 넣지 않는 것 | 이유 |
| --- | --- |
| 방문 순서 번호 | 담당자가 필요 없다고 판단함. README와 다름 (L-01) |
| 필터 | README 범위 밖 |
| 주소 입력 | 검색·지도 연동이 없어 쓰이는 곳이 없음 |
| 지도를 직접 클릭해 핀 찍기 | 시·도 select로 대신함 |
| 시·군·구 단위 지역 | SVG에 시·도 경계만 있음 |
| 장소에서 다이어리로 가는 버튼 | 보류 (L-06) |
| 장소 상세 다이얼로그 | 3~4일 일정. 카드에 내용과 수정·삭제 버튼을 바로 둔다 |
| 여행 상세에서 고른 여행을 넘겨받아 들어오기 | 3~4일 일정. 여행 상세에 장소 목록이 이미 보인다 (L-08, R-009) |

### 7. 알고 있는 한계
- 한국 지도 1장이라 해외 장소는 기록할 수 없다. 여행기록의 여행지는 자유 입력이라 해외 여행도 등록되지만, 그 여행의 장소는 국내 시·도로만 넣을 수 있다.
- 같은 시·도의 장소는 핀이 겹친다. (핀 개수 표시와 카드로 보완)
- 핀 위치는 시·도 가운데라 실제 위치와 다르다.
- 장소 화면에서는 핀을 누르기 전에는 장소 카드가 보이지 않는다. 여행의 장소 전체는 여행 상세에서 본다.

## 4. 여행 다이어리 (담당: 건용)

### 1. 목적
여행 중 날짜별로 일기를 쓴다. (D-003)

### 2. 사용자가 할 수 있는 일
- 일기를 쓴다. 같은 날짜에 여러 편을 쓸 수 있다.
- 한 여행의 일기를 본다.
- 저장한 일기를 고친다. 쓸 때와 같은 규칙을 따른다.
- 저장한 일기를 지운다. 지우기 전에 "정말 지울까요?"라고 한 번 더 묻는다.

### 3. 입력하는 정보
| 항목 | 필수 | 규칙 | 예 |
| --- | --- | --- | --- |
| 날짜 | 필수 | `YYYY-MM-DD`, 그 여행의 기간 안에서만 고를 수 있다 | |
| 시각 | 필수 | | |
| 제목 | 필수 | 최대 50자. 넘으면 저장되지 않고 사용자에게 알려 준다 | |
| 본문 | 선택 | 글자 수 제한 없음. 비어 있어도 자동으로 채우지 않는다 | |
| 기분 | 필수 | 아래 5개 중 하나. 화면에는 이모지만 보인다 | 😊 |
- 필수 항목이 하나라도 비어 있으면 저장되지 않고 사용자에게 알려 준다.

| 기분 | 이모지 |
| --- | --- |
| 설렘 | 🤩 |
| 행복 | 😊 |
| 평온 | 😌 |
| 피곤 | 😩 |
| 아쉬움 | 🥲 |

### 4. 보는 규칙
- 한 여행의 일기를 날짜·시각이 오래된 것부터 보여 준다.

### 5. 다른 기능과의 연결

- 날짜는 여행기록의 기간 안에서만 고를 수 있다.

## 5. Home (담당: 은희)

> README: 첫 화면(Home, `/`)은 세 기능의 데이터를 모아 보여 주는 화면이다. (D-004)
> 3~4일 일정에 맞춰, 서준·건용에게 새 API를 부탁하지 않아도 되는 블록부터 만든다.

### 1. 목적
세 기능의 가장 최근 기록을 카드 하나씩 간결하게 보여 주고, 카드를 누르면 해당 메뉴로 보낸다.

### 2. 사용자가 할 수 있는 일
- 최근 여행·장소·일기를 카드 하나씩 본다. (일기 카드는 C 블록 조건을 따른다)
- 카드를 눌러 해당 메뉴로 간다. 최근 여행 카드만 그 여행의 상세 화면으로 간다. (H-03)
- "새 여행 만들기" 버튼으로 여행 추가 화면에 간다. (H-04)

### 3. 입력하는 정보
해당 없음 (Home은 보여 주기만 한다)

### 4. 보는 규칙
| 블록 | 보이는 것 | 개수 | "최근" 기준 | 가져오는 곳 | 카드를 누르면 | 만들기 |
| --- | --- | --- | --- | --- | --- | --- |
| A. 최근 여행 | 여행명, 여행지, 기간 | 1 | 시작일 늦은 순 | 여행 목록 API(서준)의 첫 번째 | 그 여행의 상세 화면. 상세 주소가 없으면 trip 메뉴 | 꼭 |
| B. 최근 장소 | 장소 이름, 지역, 방문 날짜 (지도 없음) | 1 | 방문 날짜 늦은 순 | 모든 여행에 걸친 최근 장소 1개 (은희 장소 API) | place 메뉴 | 꼭 |
| C. 최근 일기 | 날짜, 기분, 제목 | 1 | 일기 날짜 늦은 순 | 모든 여행에 걸친 최근 일기 1개 (건용 다이어리 API) | diary 메뉴 | 건용이 동의할 때만 |
| D. 바로가기 | "새 여행 만들기" 버튼 | 1 | — | — | 여행 추가 화면. 주소가 없으면 trip 메뉴 | 꼭 |
- 날짜가 같으면 나중에 등록한 것(`id`가 큰 것)이 앞이다. "최근" 기준은 모두 사용자가 적은 날짜다. (H-02, H-05)
- 블록마다 카드는 하나다. Home에는 지도를 넣지 않는다.
- 카드를 누르는 것과 "더 보기"가 같은 곳으로 가므로, 따로 "더 보기"는 두지 않는다.

### 5. 다른 기능과의 연결
- 세 기능의 데이터를 가져다 쓰기만 한다. 카드에 보일 항목은 각 기능의 데이터가 정해지면 맞춘다.
- A는 서준이 이미 만드는 여행 목록 API를 그대로 쓴다. 서준이 Home 때문에 따로 만들 API는 없다.
- B는 은희의 장소 API에 "모든 여행에 걸친 최근 1개"를 둔다.
- C는 건용의 다이어리 API에 같은 주소가 있어야 한다. 없으면 C 블록을 빼고 A·B·D만 보여 준다. (H-01)
- place·diary 메뉴로 가면 여행 select가 빈 상태로 "여행을 골라 주세요"가 먼저 보인다.

### 6. 이 기능에서 따로 만들지 않는 것
| 넣지 않는 것 | 이유 |
| --- | --- |
| Home 지도 | 장소 화면에 지도가 있고, Home은 간결하게 둔다 |
| "여행 3개, 장소 12곳" 같은 숫자 요약 | README "통계"에 해당할 수 있음 |
| "장소 추가", "일기 쓰기" 바로가기 | 여행을 먼저 골라야 해서 카드를 눌러 메뉴로 가는 것과 같다 |
| 블록마다 여러 개 보여 주기 | 전체는 각 메뉴에서 본다 |
| 카드를 눌러 그 장소·일기가 바로 보이는 상태로 들어가기 | 3~4일 일정. 메뉴로만 보낸다 (H-03) |
| 카드와 따로 있는 "더 보기" | 카드를 누르면 같은 곳으로 간다 |

### 7. 알고 있는 한계
- C는 건용의 다이어리 API에 최근 1개 주소가 정해지기 전에는 데이터를 가져올 방법이 없다.
- 장소·일기 카드를 눌러도 그 항목이 바로 보이지 않는다. 메뉴에서 여행을 다시 골라야 한다.

### 8. 다른 문서로 넘길 것
| 내용 | 문서 |
| --- | --- |
| PC·모바일 배치(반응형), 카드 모양 | `SCREEN-SPEC`, `DESIGN` |
| 블록별 빈 상태·로딩·오류 | `SCREEN-SPEC` |
| Home이 쓰는 API 주소와 응답 모양 | `API-SPEC` |

### 9. 열린 질문
| 번호 | 내용 | 함께 볼 사람 | 정하면 고칠 곳 |
| --- | --- | --- | --- |
| H-01 | B는 은희 장소 API에 "모든 여행에 걸친 최근 1개"를 둔다. C는 건용 다이어리 API에 같은 주소를 둘지. 안 두면 C 블록을 뺀다 | 건용 | `API-SPEC` |
| H-02 | "최근" 기준: 여행 시작일 늦은 순, 방문 날짜 늦은 순, 일기 날짜 늦은 순, 같으면 나중에 등록한 것이 앞 | 서준·건용 | `API-SPEC`, `DATA-MODEL` |
| H-04 | "새 여행 만들기" 버튼으로 여행 추가 화면에 바로 들어가는 방법. 주소가 없으면 trip 메뉴로 보낸다 | 서준 | `ARCHITECTURE`, `SCREEN-SPEC` |
| H-05 | 같은 날짜면 `id`가 큰 것을 나중에 등록한 것으로 본다. 만든 시각은 따로 저장하지 않는다 (L-11과 같음) | 건용 (DB)·전원 | `DATA-MODEL` |

- 이번 조정으로 닫은 질문
  - H-03 Home 카드를 눌렀을 때: 최근 여행 카드만 여행 상세로, 나머지는 메뉴로 보낸다. (은희 추천안)
