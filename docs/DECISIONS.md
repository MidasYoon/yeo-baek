## D-004 공통 뼈대·첫 화면 담당

- **결정:** 공통 파일(라우터 등록, 화면 레이아웃, DB 설정)은 건용이, 첫 화면(Home)은 은희가 맡는다.
- **배경:** 두 역할의 담당이 "미정"이라 공통 뼈대 작업을 시작할 사람이 없었다.
- **이유:** 한 명씩 추첨으로 정했다. (AI가 임의로 고른 결과이며, 추첨 프로그램은 쓰지 않았다.)
- **다른 선택지:** 여행기록 담당(서준)이 공통 뼈대와 Home을 함께 맡는 안
- **누가·근거:** 사람이 추첨 결과를 승인함
- **영향:** 건용은 여행 다이어리와 공통 뼈대를, 은희는 여행지 정보와 Home을 함께 맡는다.
- **다시 볼 조건:** 한 사람에게 작업이 몰려 일정이 밀릴 때
- **상태:** 유효
- **날짜:** 2026-10-19

## D-005 설계 문서의 공통·개별 구분

- **결정:**
  - 공통 문서: `PRD`, `ARCHITECTURE`, `DATA-MODEL`, `API-SPEC`
  - 개별 문서: `SCREEN-SPEC`, `TEST-PLAN` (`TEST-PLAN`에는 기능 사이 연결·회귀 검사를 다루는 공통 절을 하나 둔다)
  - 모든 문서는 `docs/` 아래 한 파일로 두고, 기능별 내용은 그 파일 안의 담당자별 절에 쓴다.
  - 절 담당: 여행기록·`trips`는 서준, 여행지 정보·`places`·Home은 은희, 여행 다이어리·`diaries`·공통 레이아웃은 건용. `ARCHITECTURE` 초안은 공통 뼈대 담당인 건용이 쓴다.
- **배경:** 기능 3개를 담당자 3명이 나눠 맡아, 문서마다 누가 무엇을 쓰는지 정해야 했다.
- **이유:** 한 사람이 바꾸면 다른 기능이 깨질 수 있는 문서(테이블 연결 `trip_id`, Home이 쓰는 목록 API 등)는 공통으로 둔다. 자기 기능 안에서 끝나는 문서는 개별로 둔다. 기능별 파일로 나누지 않으면 `AGENTS.md`의 문서 목록을 바꾸지 않아도 된다.
- **다른 선택지:** 개별 문서를 기능별 파일로 나누는 안 (예: `docs/screen-spec/trips.md`). Git 충돌은 줄지만 `AGENTS.md`·`README.md`의 문서 목록을 고쳐야 한다.
- **누가·근거:** 사람이 AI의 제안 중 "한 파일 안에 담당자별 절" 안을 승인함
- **영향:** 같은 파일을 여러 명이 고치므로 Git 충돌이 날 수 있다. 공통 문서를 고칠 때는 팀에 먼저 알린다.
- **다시 볼 조건:** 같은 문서에서 Git 충돌이 자주 날 때
- **상태:** 대체됨 (D-007)
- **날짜:** 2026-10-19

## D-007 설계 문서의 공통·개별 구분과 고치는 규칙

- **결정:**
  - 공통 설계 문서: `PRD`, `ARCHITECTURE`, `DATA-MODEL`, `API-SPEC`
  - 개별 문서: `SCREEN-SPEC`, `TEST-PLAN` (`TEST-PLAN`에는 기능 사이 연결·회귀 검사를 다루는 공통 절을 하나 둔다)
  - 모든 문서는 `docs/` 아래 한 파일로 두고, 기능별 내용은 그 파일 안의 담당자별 절에 쓴다.
  - 절 담당: 여행기록·`trips`는 서준, 여행지 정보·`places`·Home은 은희, 여행 다이어리·`diaries`·공통 레이아웃은 건용. `ARCHITECTURE` 초안은 공통 뼈대 담당인 건용이 쓴다.
  - 공통 설계 문서는 공통 문서(README, AGENTS, DECISIONS 등)와 같이 팀이 합의한 뒤에만 고친다. 담당자별 절도 마찬가지다.
- **배경:** D-005는 공통 설계 문서를 "팀에 먼저 알리고" 고친다고 했고, AGENTS는 공통 문서(README, AGENTS, DECISIONS 등)를 "합의한 뒤에만" 고친다고 했다. 같은 "공통 문서"라는 말이 다른 문서를 가리키고 규칙도 달랐다.
- **이유:** 한 사람이 바꾸면 다른 기능이 깨질 수 있는 문서이므로, 다른 공통 문서와 같은 규칙으로 맞춘다.
- **다른 선택지:** 이름을 "공통 규칙 문서"(합의 후 수정)와 "공통 설계 문서"(먼저 알림)로 나누고 규칙은 따로 두는 안
- **누가·근거:** 사람이 "규칙을 하나로" 안을 고르고, 팀 합의로 보고 진행하라고 승인함
- **영향:** 자기 담당 절을 고칠 때도 팀 합의가 필요해 작업이 느려질 수 있다. 같은 파일을 여러 명이 고치므로 Git 충돌이 날 수 있다. `AGENTS.md`, `README.md`의 규칙 문구와 D-005를 가리키던 곳(`docs/PRD.md`, `docs/PLAN.md`)을 함께 고쳤다.
- **다시 볼 조건:** 같은 문서에서 Git 충돌이 자주 나거나, 합의를 기다리느라 일정이 밀릴 때
- **상태:** 유효
- **날짜:** 2026-10-20
