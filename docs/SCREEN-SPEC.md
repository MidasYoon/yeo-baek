## 3. 여행기록 (담당: 서준)

> 근거: D-001, PRD 2절

### 1. 화면 주소
| 화면 | 주소 | 상태 |
| --- | --- | --- |
| 여행 목록 | `/trip` | 확정 (D-012) |
| 여행 상세 | `/trip/:id` | 정함 (2026-10-20). Home 최근 여행 카드가 이 주소로 간다 (PRD R-H-005) |
| 여행 추가 | `/trip/new` | 정함 (2026-10-20). Home "새 여행 만들기" 버튼이 이 주소로 간다 (PRD H-04) |
| 여행 수정 | `/trip/:id/edit` | 정함 (2026-10-20) |
- `:id`는 여행의 `id`다.
- 세 주소는 `frontend/src/App.jsx`(팀 공동)에 등록하므로 팀 합의가 필요하다 (D-013).

### 2. 보이는 것
- 여행 목록 (`/trip`)
  - 맨 위에 "새 여행 만들기" 버튼 (AI 제안)
  - 여행마다 카드 하나: 여행명, 여행지, 기간(`YYYY-MM-DD ~ YYYY-MM-DD`). 여행 정보는 목록에 보이지 않는다 (AI 제안)
  - 순서는 시작일이 늦은 순, 같으면 `id`가 큰 것이 위 (R-T-007, R-T-016)
- 여행 상세 (`/trip/:id`)
  - 여행명, 여행지, 기간, 여행 정보. 수정·삭제 버튼, "목록으로" 버튼 (AI 제안)
  - 그 아래에 "장소" 목록과 "일기" 목록 (R-T-009). 항목 모양은 7번 열린 질문 R-T-009
  - 목록의 장소·일기를 눌러도 다른 화면으로 가지 않는다 (PRD L-08, AI 제안)
- 추가·수정 폼 (`/trip/new`, `/trip/:id/edit`)
  - 여행명, 여행지, 시작일, 종료일, 여행 정보(여러 줄 입력 칸). 저장·취소 버튼 (PRD 2절 3번)
  - 수정 폼은 지금 값이 채워진 채로 열린다 (AI 제안)

### 4. 입력 오류와 확인 창
입력 오류는 문제가 있는 칸 바로 아래에 한 줄로 보인다. 오류가 하나라도 있으면 저장되지 않는다.

| 상황 | 보이는 안내 | PRD 번호 |
| --- | --- | --- |
| 필수 항목을 비움 | 그 칸 아래: "여행명을 적어 주세요" (여행지·시작일·종료일도 같은 꼴) (AI 제안 문구) | R-T-004 |
| 여행명·여행지가 20자를 넘음 | 그 칸 아래: "20자까지 쓸 수 있어요" (AI 제안 문구) | R-T-018 |
| 종료일이 시작일보다 빠름 | 종료일 칸 아래: "종료일은 시작일과 같거나 뒤여야 해요" (AI 제안 문구) | R-T-005 |
| 지우기 전 확인 | 확인 창: "정말 지울까요?" + 지우기·취소 버튼 (공통) | R-T-011 |
| 장소·일기가 붙은 여행을 지우려 함 | "삭제"를 누르면 확인 창 대신: "장소 N곳, 일기 N편이 있어 지울 수 없어요. 먼저 지워 주세요." | R-T-012 |
| 새 기간 밖에 장소·일기가 있어 기간을 고칠 수 없음 | 종료일 칸 아래: "새 기간 밖에 장소 N곳, 일기 N편이 있어요. 먼저 날짜를 고치거나 지워 주세요." | R-T-017, R-T-019 |
- N이 0인 쪽은 빼고 적는다. 예: "일기 2편이 있어 지울 수 없어요." (AI 제안)

### 5. 빈 상태 · 로딩 · 오류
| 화면·영역 | 빈 상태 | 로딩 | 오류 |
| --- | --- | --- | --- |
| 여행 목록 | "아직 기록한 여행이 없어요." + "새 여행 만들기" 버튼 | "불러오는 중…" | "여행 목록을 불러오지 못했어요." + "다시 시도" 버튼 |

## 5. 여행 다이어리 (담당: 건용)

> 근거: D-003, PRD 4절

### 1. 화면 주소
| 화면 | 주소 | 상태 |
| --- | --- | --- |
| 여행 다이어리 | `/diary` | 확정 (D-012) |
| 일기 쓰기·고치기 폼 | 따로 주소를 두지 않는다. `/diary` 안에서 목록 위에 펼친다 (AI 제안) | 정함 (2026-10-21) |
- 안쪽 주소가 없으므로 `frontend/src/App.jsx`(팀 공동)에 더 등록할 주소가 없다 (D-013).

### 2. 보이는 것
- 여행 select (R-D-001). 항목 모양은 1절 공통을 따른다.
- 일기 목록 (R-D-008)
  - 같은 날짜의 일기는 날짜 제목(`YYYY-MM-DD`) 아래 한 묶음으로 보인다 (R-D-018)
  - 묶음은 날짜가 오래된 순, 묶음 안은 시각이 오래된 순, 같으면 `id`가 작은 것이 위
  - 접힌 줄: 시각(`오전/오후 H:MM`), 기분 이모지, 제목. 날짜는 묶음 제목에 있으므로 줄에서 뺀다
  - 줄을 누르면 펼쳐진다: 본문, 수정·삭제 버튼 (AI 제안: 버튼은 펼친 줄 안에만 둔다)
  - 긴 제목은 자르지 않고 줄을 바꿔 다 보여 준다
- 기분 표시: 이모지만 보인다. 기분 이름은 보여 주지 않는다 (R-D-006, R-D-019)
- 쓰기·고치기 폼 (목록 위에 펼침, 쓰기와 고치기가 같은 폼) (PRD 4절 3번)
  - 날짜: 달력 입력 칸. 처음 값은 그 여행의 시작일. 여행 기간 밖 날짜는 달력에서 고를 수 없다 (R-D-003)
  - 시각: 오전/오후 · 시(1~12) · 분(00~59) select 3개. PRD의 `오전/오후 H:MM` 꼴에 맞춘다 (R-D-004, 분 단위는 AI 제안)
  - 제목: 한 줄 입력 칸. 50자가 넘어도 입력은 막지 않고, 저장할 때 알려 준다 (R-D-005, R-D-007)
  - 본문: 여러 줄 입력 칸 (R-D-005)
  - 기분: 이모지 버튼 5개(🤩😊😌😩🥲) 중 하나를 누른다. 이름은 보여 주지 않는다 (R-D-006)
  - 저장·취소 버튼
  - 고치기 폼은 지금 값이 채워진 채로 열린다 (AI 제안)
