# 화면 명세 (SCREEN-SPEC)

> 화면에서 보이는 것과 할 수 있는 행동을 적는다. 무엇을 만들지는 `docs/PRD.md`, 구조는 `docs/ARCHITECTURE.md`를 따른다.
> 한 파일 안에 담당자별 절로 쓰고, 담당자별 절도 팀이 합의한 뒤에만 고친다 (D-007).
> 기능별 절(2~6)은 모두 같은 목차 1~7을 따른다. 근거가 되는 PRD 번호를 괄호로 적는다.
> 색·글자·여백 같은 모양 규칙은 적지 않는다 (`docs/DESIGN.md` 몫, D-023).
> "제안"이나 "확인 필요"가 붙은 내용은 확정이 아니다.

## 2. 공통 레이아웃 (담당: 건용)

> 근거: D-004, D-010, D-012. 파일: `frontend/src/components/Layout/`. 고칠 때는 팀이 합의한다 (D-007).

### 1. 화면 주소
모든 화면(`/`, `/trip`과 그 안쪽 주소, `/place`, `/diary`)과 없는 주소 화면을 감싼다.

### 2. 보이는 것
- 네비: 화면 맨 위에 가로 한 줄. 왼쪽에 앱 이름 "여백", 그 옆에 메뉴 `trip · place · diary` 3개 (D-012, PRD L-07)
- 지금 있는 메뉴는 글자를 굵게 하고 밑줄을 긋는다.
  - 안쪽 주소(`/trip/:id`, `/trip/new` 등)에 있을 때도 그 메뉴를 표시한다.
  - Home(`/`)에서는 표시하는 메뉴가 없다.
  - 없는 주소 화면에서도 표시하는 메뉴가 없다. (2026-10-21 팀 합의, TEST-PLAN T-L-04)
- 꼬리말(푸터)은 두지 않는다.
- 브라우저 탭 제목은 모든 화면에서 "여백"이다.
- 반응형 구조
  - 화면 폭 768px을 기준으로 나눈다. 768px 미만은 모바일, 768px 이상은 PC다.
  - 모바일에서도 네비는 맨 위 가로 한 줄 그대로다.
  - 각 화면 안쪽의 배치(지도와 목록, Home 블록 등)는 각 절의 담당자가 그 절 "2. 보이는 것"에 적는다. 이 절에서는 폭 기준과 네비만 정한다.

## 3. 여행기록 (담당: 서준)

> 근거: D-001, PRD 2절

### 1. 화면 주소
| 화면 | 주소 | 상태 |
| --- | --- | --- |
| 여행 목록 | `/trip` | 확정 (D-012) |
| 여행 상세 | `/trip/:id` | 정함 (2026-10-20). Home 최근 여행 카드가 이 주소로 간다 (PRD R-H-005) |
| 여행 추가 | `/trip/new` | 정함 (2026-10-20). Home "새 여행 만들기" 버튼이 이 주소로 간다 (PRD H-04) |
| 여행 수정 | `/trip/:id/edit` | 정함 (2026-10-20) |
- `:id`는 여행의 `id`다.
- 세 주소는 `frontend/src/App.jsx`(팀 공동)에 등록하므로 팀 합의가 필요하다 (D-013).

### 2. 보이는 것
- 여행 목록 (`/trip`)
  - 맨 위에 "새 여행 만들기" 버튼 (AI 제안)
  - 여행마다 카드 하나: 여행명, 여행지, 기간(`YYYY-MM-DD ~ YYYY-MM-DD`). 여행 정보는 목록에 보이지 않는다 (AI 제안)
  - 순서는 시작일이 늦은 순, 같으면 `id`가 큰 것이 위 (R-T-007, R-T-016)
- 여행 상세 (`/trip/:id`)
  - 여행명, 여행지, 기간, 여행 정보. 수정·삭제 버튼, "목록으로" 버튼 (AI 제안)
  - 그 아래에 "장소" 목록과 "일기" 목록 (R-T-009). 장소는 4절 카드 모양, 일기는 5절 목록 모양(날짜 묶음, 접힌 줄)과 같고 순서도 같다. 수정·삭제 버튼은 없다 (2026-10-21)
  - 목록의 장소·일기를 눌러도 다른 화면으로 가지 않는다 (PRD L-08, AI 제안)
- 추가·수정 폼 (`/trip/new`, `/trip/:id/edit`)
  - 맨 위 제목: 추가 폼은 "새 여행 만들기" (2026-10-22, PLAN P-24). 수정 폼은 "여행 수정" (2026-10-22, PLAN P-25)
  - 여행명, 여행지, 시작일, 종료일, 여행 정보(여러 줄 입력 칸). 저장·취소 버튼 (PRD 2절 3번)
  - 수정 폼은 지금 값이 채워진 채로 열린다 (AI 제안)

### 4. 입력 오류와 확인 창
입력 오류는 문제가 있는 칸 바로 아래에 한 줄로 보인다. 오류가 하나라도 있으면 저장되지 않는다 (1절 공통).

| 상황 | 보이는 안내 | PRD 번호 |
| --- | --- | --- |
| 필수 항목을 비움 | 그 칸 아래: "여행명을 적어 주세요" (여행지·시작일·종료일도 같은 꼴) (AI 제안 문구) | R-T-004 |
| 여행명·여행지가 20자를 넘음 | 그 칸 아래: "20자까지 쓸 수 있어요" (AI 제안 문구) | R-T-018 |
| 종료일이 시작일보다 빠름 | 종료일 칸 아래: "종료일은 시작일과 같거나 뒤여야 해요" (AI 제안 문구) | R-T-005 |
| 지우기 전 확인 | 확인 창: "정말 지울까요?" + 지우기·취소 버튼 (공통) | R-T-011 |
| 장소·일기가 붙은 여행을 지우려 함 | "삭제"를 누르면 확인 창 대신: "장소 N곳, 일기 N편이 있어 지울 수 없어요. 먼저 지워 주세요." | R-T-012 |
| 새 기간 밖에 장소·일기가 있어 기간을 고칠 수 없음 | 종료일 칸 아래: "새 기간 밖에 장소 N곳, 일기 N편이 있어요. 먼저 날짜를 고치거나 지워 주세요." | R-T-017, R-T-019 |
- N이 0인 쪽은 빼고 적는다. 예: "일기 2편이 있어 지울 수 없어요." (AI 제안)
- 공백만 적은 여행명·여행지는 화면에서 막지 않는다. 서버가 `422`로 막고, 화면은 공통 저장 실패 문구를 보인다 (D-021).

## 4. 여행지 정보 (담당: 은희)

> 근거: D-002, D-006, PRD 3절

### 1. 화면 주소
| 화면 | 주소 | 상태 |
| --- | --- | --- |
| 여행지 정보 (목록) | `/place` | 확정 (D-012) |
| 여행지 정보 (여행을 고른 목록) | `/place?trip=:tripId` | 정함 (2026-10-21) |

- `:tripId`는 여행의 `id`, `:id`는 장소의 `id`다. 장소 수정은 장소가 어느 여행에 붙어 있는지 알므로 여행 번호를 따로 넘기지 않는다.

### 2. 보이는 것
**목록 화면 (`/place`, `/place?trip=:tripId`)** — 위에서 아래 순서로 보인다.

- 여행 select (R-P-001, R-P-002)
  - 주소에 여행 번호가 없으면 비어 있고 "여행을 골라 주세요"가 보인다. 있으면 그 여행이 골라진 채로 보인다 (1절 공통)
  - 네비 메뉴의 place로 들어와도, Home의 "최근 장소" 카드로 들어와도 처음 모습은 같다 (PRD 3절 4번, H-03)
  - 항목 하나: 여행명 (`YYYY-MM-DD ~ YYYY-MM-DD`) (1절 공통)
  - 항목 순서는 여행 목록과 같다: 시작일이 늦은 순, 같으면 `id`가 큰 것이 위 (R-T-007, R-T-016)
- 여행을 고르기 전: select와 안내만 보인다. "장소 추가" 버튼, 지도, 카드는 보이지 않는다 (1절 공통)
- 여행을 고른 뒤
  - "장소 추가" 버튼 (AI 제안)
  - 지도: 한국 지도 SVG 1장 (R-P-005)
    - 장소가 있는 시·도의 가운데에만 핀이 보인다 (R-P-005)
    - 핀 위에 그 시·도의 장소 개수가 보인다. 1곳이어도 숫자를 보인다 (R-P-006, D-014)
    - 눌린 핀은 다른 핀과 구분되게 보인다. 한 번에 하나만 눌린다 (R-P-007)
  - 장소 카드 목록 (R-P-008, R-P-020)
    - 카드 하나: 장소 이름, 지역(시·도 이름), 방문 날짜(`YYYY-MM-DD`), 메모, 수정·삭제 버튼 (R-P-008)
    - 메모가 없으면 메모 줄이 보이지 않는다 (AI 제안)
    - 순서: 방문 날짜가 오래된 순, 같으면 `id`가 작은 것이 앞 (R-P-009)
    - 핀을 누르면 그 지역 카드가 다른 카드와 구분되게 강조된다. 다른 카드도 그대로 보인다 (R-P-007)
    - 강조된 카드 중 첫 카드가 화면에 보이도록 목록이 움직인다 (AI 제안)

**추가·수정 폼 화면 (`/place/new?trip=:tripId`, `/place/:id/edit`)**

- 맨 위: 제목 "장소 추가" 또는 "장소 수정". 그 아래에 그 여행의 이름과 기간이 보인다. 여행 select는 없다 (1절 공통)
- 지역: 시·도 17개 select. 처음에는 비어 있다 (R-P-004). 칸 아래에 흐린 도움말 "국내 시·도만 고를 수 있어요"가 늘 보인다 (R-P-021)
- 장소 이름: 한 줄 입력 칸 (R-P-004)
- 방문 날짜: 날짜 입력 칸. 그 여행의 기간 밖 날짜는 고를 수 없다 (R-P-004, 1절 공통)
- 메모: 한 줄 입력 칸, 선택 (R-P-004)
- 저장·취소 버튼
- 수정 폼은 지금 값이 채워진 채로 열린다 (AI 제안. 참고: 3절과 같은 동작)

**PC·모바일 배치** (AI 제안)
- 화면 폭 기준은 2절을 따른다 (768px).
- 목록 화면은 768px 이상·미만 모두 위에서 아래 한 줄로 쌓는다: select → "장소 추가" → 지도 → 카드 목록
- 768px 미만에서는 지도가 화면 폭에 맞춰 줄어든다. 카드는 한 줄에 하나다.

    - 같은 날짜의 일기는 날짜 제목(`YYYY-MM-DD`) 아래 한 묶음으로 보인다 (R-D-018)
    - 묶음은 날짜가 오래된 순, 묶음 안은 시각이 오래된 순, 같으면 `id`가 작은 것이 위
    - 접힌 줄: 시각(`오전/오후 H:MM`), 기분 이모지, 제목. 날짜는 묶음 제목에 있으므로 줄에서 뺀다
    - 줄을 누르면 펼쳐진다: 본문, 수정·삭제 버튼 (AI 제안: 버튼은 펼친 줄 안에만 둔다)
    - 긴 제목은 자르지 않고 줄을 바꿔 다 보여 준다
- 기분 표시: 이모지만 보인다. 기분 이름은 보여 주지 않는다 (R-D-006, R-D-019)

**쓰기·고치기 폼 화면 (`/diary/new?trip=:tripId`, `/diary/:id/edit`)** (쓰기와 고치기가 같은 폼) (PRD 4절 3번)

- 맨 위: 제목 "새 일기 쓰기" 또는 "일기 고치기" (AI 제안). 그 아래에 그 여행의 이름과 기간이 보인다. 여행 select는 없다 (1절 공통)
- 날짜: 달력 입력 칸. 처음 값은 그 여행의 시작일. 여행 기간 밖 날짜는 달력에서 고를 수 없다 (R-D-003)
- 시각: 오전/오후 · 시(1~12) · 분(00~59) select 3개. PRD의 `오전/오후 H:MM` 꼴에 맞춘다 (R-D-004, 분 단위는 AI 제안)
- 자정·정오: `00:30`은 `오전 12:30`, `12:05`는 `오후 12:05`로 보인다. 목록과 폼의 시각 select가 같다. (2026-10-21 팀 합의, TEST-PLAN T-D-07)
- 제목: 한 줄 입력 칸. 50자가 넘어도 입력은 막지 않고, 저장할 때 알려 준다 (R-D-005, R-D-007)
- 본문: 여러 줄 입력 칸 (R-D-005)
- 기분: 이모지 버튼 5개(🤩😊😌😩🥲) 중 하나를 누른다. 이름은 보여 주지 않는다 (R-D-006)
- 저장·취소 버튼
- 고치기 폼은 지금 값이 채워진 채로 열린다 (AI 제안)
