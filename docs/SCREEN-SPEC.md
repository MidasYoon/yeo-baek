## 3. 여행기록 (담당: 서준)

> 근거: D-001, PRD 2절

### 1. 화면 주소
| 화면 | 주소 | 상태 |
| --- | --- | --- |
| 여행 목록 | `/trip` | 확정 (D-012) |
| 여행 상세 | `/trip/:id` | 정함 (2026-10-20). Home 최근 여행 카드가 이 주소로 간다 (PRD R-H-005) |
| 여행 추가 | `/trip/new` | 정함 (2026-10-20). Home "새 여행 만들기" 버튼이 이 주소로 간다 (PRD H-04) |
| 여행 수정 | `/trip/:id/edit` | 정함 (2026-10-20) |
- `:id`는 여행의 `id`다.
- 세 주소는 `frontend/src/App.jsx`(팀 공동)에 등록하므로 팀 합의가 필요하다 (D-013).

### 2. 보이는 것
- 여행 목록 (`/trip`)
  - 맨 위에 "새 여행 만들기" 버튼 (AI 제안)
  - 여행마다 카드 하나: 여행명, 여행지, 기간(`YYYY-MM-DD ~ YYYY-MM-DD`). 여행 정보는 목록에 보이지 않는다 (AI 제안)
  - 순서는 시작일이 늦은 순, 같으면 `id`가 큰 것이 위 (R-T-007, R-T-016)
- 여행 상세 (`/trip/:id`)
  - 여행명, 여행지, 기간, 여행 정보. 수정·삭제 버튼, "목록으로" 버튼 (AI 제안)
  - 그 아래에 "장소" 목록과 "일기" 목록 (R-T-009). 항목 모양은 7번 열린 질문 R-T-009
  - 목록의 장소·일기를 눌러도 다른 화면으로 가지 않는다 (PRD L-08, AI 제안)
- 추가·수정 폼 (`/trip/new`, `/trip/:id/edit`)
  - 여행명, 여행지, 시작일, 종료일, 여행 정보(여러 줄 입력 칸). 저장·취소 버튼 (PRD 2절 3번)
  - 수정 폼은 지금 값이 채워진 채로 열린다 (AI 제안)

### 4. 입력 오류와 확인 창
입력 오류는 문제가 있는 칸 바로 아래에 한 줄로 보인다. 오류가 하나라도 있으면 저장되지 않는다.

| 상황 | 보이는 안내 | PRD 번호 |
| --- | --- | --- |
| 필수 항목을 비움 | 그 칸 아래: "여행명을 적어 주세요" (여행지·시작일·종료일도 같은 꼴) (AI 제안 문구) | R-T-004 |
| 여행명·여행지가 20자를 넘음 | 그 칸 아래: "20자까지 쓸 수 있어요" (AI 제안 문구) | R-T-018 |
| 종료일이 시작일보다 빠름 | 종료일 칸 아래: "종료일은 시작일과 같거나 뒤여야 해요" (AI 제안 문구) | R-T-005 |
| 지우기 전 확인 | 확인 창: "정말 지울까요?" + 지우기·취소 버튼 (공통) | R-T-011 |
| 장소·일기가 붙은 여행을 지우려 함 | "삭제"를 누르면 확인 창 대신: "장소 N곳, 일기 N편이 있어 지울 수 없어요. 먼저 지워 주세요." | R-T-012 |
| 새 기간 밖에 장소·일기가 있어 기간을 고칠 수 없음 | 종료일 칸 아래: "새 기간 밖에 장소 N곳, 일기 N편이 있어요. 먼저 날짜를 고치거나 지워 주세요." | R-T-017, R-T-019 |
- N이 0인 쪽은 빼고 적는다. 예: "일기 2편이 있어 지울 수 없어요." (AI 제안)

## 4. 여행지 정보 (담당: 은희)

> 근거: D-002, D-006, PRD 3절

### 1. 화면 주소
| 화면 | 주소 | 상태 |
| --- | --- | --- |
| 여행지 정보 | `/place` | 확정 (D-012) |
| 장소 추가·수정 폼 | 따로 주소를 두지 않고 `/place` 안에서 펼친다 | AI 제안 |
- 이유: 폼을 열어도 고른 여행·지도·카드가 그대로 남아 여행을 다시 고르지 않아도 된다. 주소를 새로 두면 `frontend/src/App.jsx`(팀 공동, D-013) 합의가 필요하고, 새로고침했을 때 고른 여행을 넘겨받는 방법도 따로 필요하다 (R-P-017 제외).
- 다른 안: `/place/new`, `/place/:id/edit` 주소를 둔다 (참고: 여행기록은 ARCHITECTURE 6절에서 안쪽 주소를 따로 정했다). (7번 열린 질문)

### 2. 보이는 것
화면 위에서 아래 순서로 보인다.

- 여행 select (R-P-001, R-P-002)
  - 처음에는 비어 있고 "여행을 골라 주세요"가 보인다 (R-P-002, L-07)
  - 네비 메뉴의 place로 들어와도, Home의 "최근 장소" 카드로 들어와도 처음 모습은 같다 (PRD 3절 4번, H-03)
  - 항목 하나: 여행명 (`YYYY-MM-DD ~ YYYY-MM-DD`) (AI 제안)
  - 항목 순서는 여행 목록과 같다: 시작일이 늦은 순, 같으면 `id`가 큰 것이 위 (R-T-007, R-T-016)
- 여행을 고르기 전: select와 안내만 보인다. "장소 추가" 버튼, 지도, 카드는 보이지 않는다 (AI 제안)
- 여행을 고른 뒤
  - "장소 추가" 버튼 (AI 제안)
  - 추가·수정 폼 (버튼을 눌렀을 때만 보인다, AI 제안)
    - 제목: "장소 추가" 또는 "장소 수정"
    - 지역: 시·도 17개 select. 처음에는 비어 있다 (R-P-004)
    - 장소 이름: 한 줄 입력 칸 (R-P-004)
    - 방문 날짜: 날짜 입력 칸. 고른 여행의 기간 밖 날짜는 고를 수 없다 (R-P-004, AI 제안)
    - 메모: 한 줄 입력 칸, 선택 (R-P-004)
    - 저장·취소 버튼
    - 수정 폼은 지금 값이 채워진 채로 열린다 (AI 제안. 참고: 3절과 같은 동작)
  - 지도: 한국 지도 SVG 1장 (R-P-005)
    - 장소가 있는 시·도의 가운데에만 핀이 보인다 (R-P-005)
    - 핀 위에 그 시·도의 장소 개수가 보인다. 1곳이어도 숫자를 보인다 (R-P-006, AI 제안)
    - 눌린 핀은 다른 핀과 구분되게 보인다. 한 번에 하나만 눌린다 (R-P-007)
  - 장소 카드 목록 (R-P-008, R-P-020)
    - 카드 하나: 장소 이름, 방문 날짜(`YYYY-MM-DD`), 메모, 수정·삭제 버튼
    - 메모가 없으면 메모 줄이 보이지 않는다 (AI 제안)
    - 순서: 방문 날짜가 오래된 순, 같으면 `id`가 작은 것이 앞 (R-P-009)
    - 핀을 누르면 그 지역 카드가 다른 카드와 구분되게 강조된다. 다른 카드도 그대로 보인다 (R-P-007)
    - 강조된 카드 중 첫 카드가 화면에 보이도록 목록이 움직인다 (AI 제안)
- PC·모바일 배치 (AI 제안)
  - 반응형 구조는 아직 미정이다 (ARCHITECTURE 6절, PRD L-07). 정해지면 그 결정을 따른다.
  - 넓은 화면·좁은 화면 모두 위에서 아래 한 줄로 쌓는다: select → "장소 추가"·폼 → 지도 → 카드 목록
  - 좁은 화면에서는 지도가 화면 폭에 맞춰 줄어든다. 카드는 한 줄에 하나다.

### 3. 할 수 있는 행동
| 행동 | 누르는 곳 | 결과 | PRD 번호 |
| --- | --- | --- | --- |
| 여행 고르기 | 여행 select | 그 여행의 지도·핀·카드가 보인다. 핀 강조는 풀리고, 열려 있던 폼은 닫힌다 (PRD 3절 4번 "select를 바꾸면 처음 모습으로") | R-P-001 |
| 핀 누르기 | 핀 | 그 핀이 눌린 모습이 되고, 그 지역 카드가 강조된다. 다른 핀을 누르면 강조가 그쪽으로 옮겨 간다 | R-P-007 |
| 강조 풀기 | 눌린 핀을 다시 누름 | 핀과 카드의 강조가 풀린다 | R-P-007 |
| 장소 추가 | "장소 추가" → 폼의 "저장" | 저장되면 폼이 닫히고, 새 장소가 순서에 맞는 자리에 카드로 들어간다. 핀이 생기거나 핀의 숫자가 늘어난다 (AI 제안) | R-P-003 |
| 장소 수정 | 카드의 "수정" → 폼의 "저장" | 저장되면 폼이 닫히고 카드에 바뀐 내용이 보인다. 지역을 바꾸면 핀도 옮겨 간다 (AI 제안) | R-P-010 |

- 강조 중에 장소를 추가·수정·삭제해도 강조는 그대로 둔다. 강조된 지역에 장소가 하나도 남지 않으면 강조가 풀린다 (AI 제안)

| 안 1. 블록별 빈 상태 | D 버튼 + A·B·C 블록에 각자의 빈 상태 문구 | 위 표 그대로라 따로 만들 것이 없다 | 처음 온 사용자에게 빈 블록 3개가 보인다 |
| 안 2. 첫 방문 화면 | "첫 여행을 만들어 보세요" + D 버튼 하나. A·B·C 블록은 보이지 않는다 | 처음 온 사용자가 무엇부터 할지 바로 안다 | A를 다 불러와야 안 2인지 알 수 있어, 그 전까지 무엇을 보일지 정해야 한다 |
- 안 2에서 여행이 없으면 장소·일기도 없다 (장소·일기는 `trip_id`로 여행에 붙는다). 그래서 A 결과만 보고 판단할 수 있다.
- 안 2에서 A가 오류이면 안 1처럼 블록별로 보인다 (AI 제안).
- AI 추천: 안 2. 다만 "여행은 있는데 장소·일기가 없는" 경우는 안 1처럼 B·C에 빈 상태 문구가 보인다.
