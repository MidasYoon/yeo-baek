## 구현 인계

- **승인한 작업 범위:** 작업 목록 P-22~P-34, P-35~P-39(사진), 그다음 P-19~P-21을 한 번에 하나씩 한다. 한 작업이 끝나고 사람이 확인한 뒤에 다음 작업으로 간다. P-35~P-39는 팀이 함께 작업한다 (2026-10-22 사람이 알림).

  - PRD에 없는 기능은 만들지 않는다. "만들지 않는 것" 목록과 앱 안의 AI 기능도 마찬가지다.
  - 확정 문서(DECISIONS의 "유효" 항목, PRD·ARCHITECTURE·SCREEN-SPEC·DATA-MODEL·API-SPEC·TEST-PLAN·DESIGN)에 정한 이름·주소·응답 모양·규칙을 바꾸지 않는다.
- **읽을 요구·설계·TEST-PLAN 항목:** 작업마다 PRD, ARCHITECTURE, SCREEN-SPEC, DATA-MODEL, API-SPEC, TEST-PLAN에서 그 작업에 해당하는 절을 읽는다.
- **다음 실행 위치와 확인할 명령:** P-20 껐다 켜고 다시 실행을 마쳤다. P-21의 검사(21-1~21-6, TEST-PLAN 230개)를 마쳤다. 21-7 기준점: 이 PLAN을 담은 `trip`을 PR로 `master`에 합치고, 다른 팀원 1명이 확인해 합친 뒤 그 `master` 커밋에 태그 `v0.1-mvp`를 단다. 태그를 단 뒤 P-21을 "완료"로 바꾸고 태그 커밋 번호를 적는 작은 커밋을 하나 더 만든다 (2026-10-23 사람이 정함, A안).
- **P-19 확인 방법:** 확인은 백엔드를 끄거나 API를 하나씩 막은 채 다섯 화면을 열어 T-C-13~T-C-18과 각 절 "4. 빈 상태 · 로딩 · 오류 검사"를 본다. 검사 전에 DB에 사람이 넣어 둔 데이터가 있는지 확인하고, 있으면 지우기 전에 묻는다 (P-33·P-34처럼 백업하고 되돌리는 방법이 있다).

- **중단 조건과 복구 방법**
  - 문서끼리 다르거나 정하지 않은 것("미정"·"제안"·"확인 필요")이 나오면 멈추고 사람에게 묻는다.
  - 문제가 생기면 마지막 커밋으로 되돌린다. 되돌리는 명령은 작업 내용을 지우므로 사람이 승인한 뒤에만 실행한다.
