## 이번 목표와 범위

- **목표:** PRD에서 "포함"인 요구사항을 동작하는 웹앱으로 만든다.
- **범위 안:** `frontend/`·`backend/` 코드 작성, 작업 목록 P-11~P-14, P-19~P-34
- **하지 않을 일:** PRD에 없는 기능, 앱 안의 AI 기능, 인터넷 공개

## 구현 인계

- **승인한 작업 범위:** 작업 목록 P-22~P-34, 그다음 P-19~P-21을 한 번에 하나씩 한다. 한 작업이 끝나고 사람이 확인한 뒤에 다음 작업으로 간다.
- **유지할 동작과 금지할 변경**
  - PRD에 없는 기능은 만들지 않는다. "만들지 않는 것" 목록과 앱 안의 AI 기능도 마찬가지다.
  - 확정 문서(DECISIONS의 "유효" 항목, PRD·ARCHITECTURE·SCREEN-SPEC·DATA-MODEL·API-SPEC·TEST-PLAN·DESIGN)에 정한 이름·주소·응답 모양·규칙을 바꾸지 않는다.
- **읽을 요구·설계·TEST-PLAN 항목:** 작업마다 PRD, ARCHITECTURE, SCREEN-SPEC, DATA-MODEL, API-SPEC, TEST-PLAN에서 그 작업에 해당하는 절을 읽는다.
- **다음 실행 위치와 확인할 명령:** P-30 일기 API부터 시작한다. 확인은 `backend/`에서 서버를 켜고 TEST-PLAN T-D-21~T-D-36, T-C-02(일기 부분)를 본다. 공백 규칙과 `PUT` 검사 순서는 D-029를 따른다.
- **검사 데이터:** 화면 검사는 TEST-PLAN 1절 예시 데이터를 넣고 한다. 데이터는 API가 생긴 뒤 `/docs`나 화면으로 넣는다.
- **중단 조건과 복구 방법**
  - 문서끼리 다르거나 정하지 않은 것("미정"·"제안"·"확인 필요")이 나오면 멈추고 사람에게 묻는다.
  - 문제가 생기면 마지막 커밋으로 되돌린다. 되돌리는 명령은 작업 내용을 지우므로 사람이 승인한 뒤에만 실행한다.
