## 4. 여행 다이어리 (담당: 건용)

### 1. 목적
여행 중 날짜별로 일기를 쓴다. (D-003)

### 2. 사용자가 할 수 있는 일
- 일기를 쓴다. 같은 날짜에 여러 편을 쓸 수 있다.
- 한 여행의 일기를 본다.
- 저장한 일기를 고친다. 쓸 때와 같은 규칙을 따른다.
- 저장한 일기를 지운다. 지우기 전에 "정말 지울까요?"라고 한 번 더 묻는다.

### 3. 입력하는 정보
| 항목 | 필수 | 규칙 | 예 |
| --- | --- | --- | --- |
| 날짜 | 필수 | `YYYY-MM-DD`, 그 여행의 기간 안에서만 고를 수 있다 | |
| 시각 | 필수 | `오전/오후 H:MM` | |
| 제목 | 필수 | 최대 50자. 넘으면 저장되지 않고 사용자에게 알려 준다 | |
| 본문 | 선택 | 글자 수 제한 없음. 비어 있어도 자동으로 채우지 않는다 | |
| 기분 | 필수 | 아래 5개 중 하나. 화면에는 이모지만 보인다 | 😊 |
- 필수 항목이 하나라도 비어 있으면 저장되지 않고 사용자에게 알려 준다.

| 기분 | 이모지 |
| --- | --- |
| 설렘 | 🤩 |
| 행복 | 😊 |
| 평온 | 😌 |
| 피곤 | 😩 |
| 아쉬움 | 🥲 |

### 4. 보는 규칙
- 한 여행의 일기를 날짜·시각이 오래된 것부터 보여 준다.
- 날짜와 시각이 같으면 먼저 저장한 일기가 위에 보인다.

### 5. 다른 기능과의 연결
- 일기는 한 여행에 속한다 (`trip_id`).
- 날짜는 여행기록의 기간 안에서만 고를 수 있다.
- 여행 기간이 바뀌어 일기 날짜가 기간 밖으로 벗어나도 일기는 지우지 않고 목록에 그대로 보여 준다. 그 일기를 고칠 때는 날짜를 기간 안으로 바꿔야 저장된다. (R-017)
- 여행을 지우면 그 여행의 일기도 함께 지워진다. (R-012, 건용 의견, 팀 확인 필요)
- 여행을 열었을 때 보이는 일기 목록은 다이어리 목록과 같은 일기를 같은 순서로 보여 준다. (R-009)

### 6. 이 기능에서 따로 만들지 않는 것
| 넣지 않는 것 | 이유 |
| --- | --- |
| 기분을 직접 글로 적기 | 정해진 목록에서 하나를 고르기로 함 |
| 일기 목록 정렬 순서 바꾸기 | README "검색·필터"와 맞닿음 |
| 지운 일기 되살리기(휴지통) | README "주요 기능"에 없음 |
| 일기에 사진 붙이기 | README "만들지 않는 것"에 "사진 업로드"가 있음 |

### 7. 알고 있는 한계
- 여행 기간 밖의 일기가 목록에 남아 있을 수 있다. 그 일기를 고칠 때는 날짜를 기간 안으로 바꿔야 한다.
- 여행을 지우면 그 여행의 일기가 모두 사라지고, 되돌릴 수 없다.
- 지운 일기는 되돌릴 수 없다. 지우기 전 확인 창으로만 막는다.
- 화면에 이모지만 보여서 기분을 잘못 알아볼 수 있다.

### 8. 다른 문서로 넘길 것
| 내용 | 문서 |
| --- | --- |
| 필수 항목을 비웠을 때, 제목이 50자를 넘었을 때의 안내 문구 | `SCREEN-SPEC` |
| 지우기 확인 창 모양 | `SCREEN-SPEC` |
| 일기가 하나도 없을 때(빈 상태)의 표시 | `SCREEN-SPEC` |
| 목록 한 줄에 보여 줄 항목과 긴 제목을 줄여 보여 주는 방법 | `SCREEN-SPEC` |
| 시각 입력 칸 모양 | `SCREEN-SPEC` |
| 이모지만 보일 때 기분 이름을 알려 주는 방법 | `SCREEN-SPEC` 또는 `DESIGN` |
| 같은 시각 일기의 순서를 위해 저장한 때를 기록하는 방법 | `DATA-MODEL` |
| 여행을 지울 때 일기를 함께 지우는 방법 | `DATA-MODEL` (PLAN P-07) |

### 9. 열린 질문
- 기간을 고쳤을 때 기간 밖 일기를 그대로 두는 방식이 R-017의 결론과 맞는지 (서준·은희 절과 맞춰 봐야 함)
- 여행을 지울 때 일기도 함께 지우는 것은 건용 의견이다. R-012와 P-07에서 팀이 확정해야 한다.
- 요구사항 번호 방식 — 팀 결정 필요
- 시각 형식(`오전/오후 H:MM`)을 팀 공통 규칙으로 올릴지
