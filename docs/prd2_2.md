# PRD 2-2 — 첫 화면 Home (은희)

> 은희 담당 초안이다. 나중에 `docs/PRD.md`의 "Home" 절로 합친다. (D-004, D-005)
> README: 첫 화면(Home, `/`)은 세 기능의 데이터를 모아 보여 주는 화면이다.
> "팀 논의 필요" 표시가 붙은 내용은 확정이 아니다. 맨 아래 [팀 논의 필요](#팀-논의-필요)를 본다.

## 1. 한 줄 요약

세 기능의 가장 최근 기록을 **카드 하나씩** 간결하게 보여 주고, 자세한 내용은 "더 보기"로 각 메뉴에 보낸다.

## 2. 만드는 순서

- Home은 **가장 마지막에** 만든다. 세 기능의 데이터를 가져다 쓰기만 하기 때문이다.
- 다만 Home이 쓸 데이터는 **지금 정해 둔다.** 각 기능이 처음부터 Home에 필요한 목록을 주도록 맞추기 위해서다.

## 3. 보이는 것

| 블록 | 보이는 것 | 개수 | "최근" 기준 | 카드를 누르면 | "더 보기" |
| --- | --- | --- | --- | --- | --- |
| A. 최근 여행 | 여행명, 여행지, 기간 | 1개 | 여행 시작일 늦은 순 | 그 여행의 상세 화면 | 여행(trip) 메뉴 |
| B. 최근 장소 | 장소 이름, 지역, 방문 날짜 (지도 없음) | 1개 | 방문 날짜 늦은 순 | 장소 화면, 그 장소가 속한 여행이 골라지고 그 장소의 지역 핀이 눌린 상태 (카드는 보이고 상세 다이얼로그는 열지 않음, `prd2_1.md` 4절) | 장소(place) 메뉴 |
| C. 최근 일기 | 날짜, 기분, 내용 앞부분 한 줄 | 1개 | 일기 날짜 늦은 순 | 다이어리 화면, 그 일기가 보이는 상태 | 다이어리(diary) 메뉴 |
| D. 바로가기 | "새 여행 만들기" 버튼 | 1개 | — | 여행 추가 화면 | — |

- 세 블록 모두 날짜가 같으면 **나중에 등록한 것**이 앞이다.
- "최근" 기준은 모두 **사용자가 적은 날짜**다. 만든 시각을 따로 저장하지 않는다.
- 카드에 보일 항목은 각 기능의 데이터가 정해지면 맞춘다. (여행 정보는 서준, 기분·내용은 건용)
- 기준·연결 방식은 서준·건용 기능과 맞춰야 한다. — **팀 논의 필요 (H-02, H-03, H-04)**

## 4. 화면 방향

- 간결하고 보기 좋게 만든다. 블록마다 카드 하나만 둔다.
- Home에는 지도를 넣지 않는다. 지도는 장소 화면에 있다.
- 반응형으로 PC와 모바일 모두 지원한다. 배치는 `SCREEN-SPEC`과 `DESIGN`에서 AI가 안을 제안하고 사람이 고른다.

## 5. 만들지 않는 것

README의 "만들지 않는 것"을 그대로 따른다. Home에서 따로 정한 것은 아래와 같다.

| 넣지 않는 것 | 이유 |
| --- | --- |
| Home 지도 (다녀온 곳 전체 지도) | 장소 화면에 지도가 있고, Home은 간결하게 둔다 |
| "여행 3개, 장소 12곳" 같은 숫자 요약 | README "통계"에 해당할 수 있음 |
| "장소 추가", "일기 쓰기" 바로가기 | 여행을 먼저 골라야 해서 "더 보기"와 같은 곳으로 간다 |
| 블록마다 여러 개 보여 주기 | Home은 맛보기만 하고, 전체는 "더 보기"로 본다 |

## 6. 알고 있는 점

- 장소(place)·다이어리(diary) 메뉴로 가는 "더 보기"를 누르면, 여행 select가 빈 상태로 "여행을 골라 주세요"가 먼저 보인다. (`prd2_1.md` 4절)
- B와 C는 여러 여행에 걸친 데이터라서, 여행 하나 단위 API만으로는 가져올 수 없다. — **팀 논의 필요 (H-01)**

## 7. 다른 문서로 넘길 것

| 내용 | 문서 |
| --- | --- |
| PC·모바일 배치, 카드 모양 | `SCREEN-SPEC`, `DESIGN` |
| 블록마다 데이터가 없을 때(빈 상태), 로딩, 오류 표시 | `SCREEN-SPEC` |
| Home이 쓰는 API 주소와 응답 모양 | `API-SPEC` (공통 문서) |

## 팀 논의 필요

| 번호 | 내용 | 함께 볼 사람 | 정하면 고칠 곳 |
| --- | --- | --- | --- |
| H-01 | Home용 목록을 **처음부터 API에 포함**하는 안을 제안한다. 최근 여행(서준), 모든 여행에 걸친 최근 장소(은희), 모든 여행에 걸친 최근 일기(건용). 거절되면 ① B·C 블록을 빼거나 ② 여행마다 따로 불러 Home에서 합친다 | 서준·건용 | `API-SPEC` |
| H-02 | "최근" 기준과 같은 날짜일 때의 순서 맞추기: 여행 시작일 늦은 순, 일기 날짜 늦은 순, 방문 날짜 늦은 순, 같으면 나중에 등록한 것이 앞 | 서준·건용 | `API-SPEC`, `DATA-MODEL` |
| H-03 | Home 카드를 눌렀을 때 특정 여행 상세(서준)와 특정 일기(건용)로 바로 들어가는 방법. 안 되면 해당 메뉴로만 보낸다 | 서준·건용 | `ARCHITECTURE`, `SCREEN-SPEC` |
| H-04 | "새 여행 만들기" 버튼으로 여행 추가 화면에 바로 들어가는 방법 | 서준 | `ARCHITECTURE`, `SCREEN-SPEC` |
| H-05 | 같은 날짜일 때 "나중에 등록한 것"을 만든 시각 없이 구분할 수 있는지 (`prd2_1.md` L-11과 같음) | 건용 (DB)·전원 | `DATA-MODEL` |

### 추천안 (은희 제안, 미확정)

> 3~4일 일정 안에 Home을 끝내기 위해 범위를 줄이는 안이다. 팀이 정하기 전까지는 확정이 아니다.

| 번호 | 추천안 | 거절되면 |
| --- | --- | --- |
| H-01 | 각 기능 API에 "모든 여행에 걸친 최근 1개"를 돌려주는 단순한 주소를 하나씩 둔다. 주소 모양은 `API-SPEC`에서 정한다 | B·C 블록을 빼고 A·D만 보여 준다 |
| H-02 | 3절의 기준(사용자가 적은 날짜 늦은 순, 같으면 나중에 등록한 것이 앞)을 그대로 쓴다 | — |
| H-03 | 이번 MVP에서는 카드를 눌러도 "더 보기"와 같은 메뉴로 보낸다. 장소 핀이 눌린 상태, 그 일기가 보이는 상태로 바로 들어가는 기능은 만들지 않는다. 여행 카드만 여행 상세 주소가 있으면 상세로 보낸다 | — |
| H-04 | 여행 추가 화면에 주소가 있으면 그 주소로 보내고, 없으면 여행(trip) 메뉴로 보낸다 | — |
| H-05 | 같은 날짜면 `id`가 큰 것을 나중에 등록한 것으로 본다. 만든 시각은 따로 저장하지 않는다 | — |

- 이 안대로면 다른 기능의 화면(장소·다이어리)을 고치지 않아도 되고, Home은 1일 이내 분량으로 본다.
- H-03 추천안을 받으면 3절 표의 "카드를 누르면" 칸과 `prd2_1.md` 4절의 "Home의 최근 장소 카드" 행을 함께 고쳐야 한다.
